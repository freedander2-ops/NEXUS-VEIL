# Secret Systems Design

## Hidden Rules & Philosophy
- Secrets must never be explicit or game-like (no achievements).
- They should create a sense of scale and unpredictability.
- Rarity is key: most secrets should occur < 1% of the time or under specific conditions.

## Trigger Philosophy
- **Time-Based**: Specific hours (e.g., 02:13 AM) trigger "deep system" modes.
- **Weather-Based**: Real-world weather (via sync) alters UI surfaces (e.g., rain creates reflections).
- **Behavioral**: Interaction sequences or previously visited states trigger evolution.

## Anomaly Categories
- **Visual Mutations**: Unstable geometry in Three.js sections, corrupted UI fragments.
- **Ghost Signals**: Hidden transmissions in OSINT, "phantom" commits in GitHub.
- **Atmospheric Shifts**: Drastic changes in global intensity and color palettes.

## Environmental Memory
- Subtly remember previously encountered anomalies to provide continuity.
- Evolving terminal messages that reflect environmental history.
