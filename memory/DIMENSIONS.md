# DIMENSIONS — NEXUS VEIL

## Core Principle

Dimensions are NOT:
simple website pages.

They are:
distinct environmental states
inside the ecosystem.

Each dimension:
- has a different purpose
- behaves differently
- reacts differently to world-state
- contains unique object types
- has its own atmospheric identity

Dimensions should feel:
like entering different realities.

---

# 1. Digital Weather

## Purpose

Digital Weather is:
the environmental nervous system.

It reflects:
- local time
- weather conditions
- ecosystem calm/tension
- global atmospheric state

It should influence:
the ENTIRE ecosystem visually.

Examples:
- rain affects reflections and fog
- nighttime changes contrast and lighting
- storms increase tension motion
- sunrise softens environmental aggression

---

## Important Rule

Digital Weather is NOT:
just another content tab.

It is:
a global environmental layer.

The section itself acts as:
an atmospheric observatory.

---

## Content Types

Allowed:
- weather signals
- atmospheric events
- environmental anomalies
- time-state objects
- ambient intelligence

Avoid:
generic dashboard widgets.

---

# 2. Cybersecurity

## Purpose

Cybersecurity represents:
high-tension ecosystem intelligence.

This dimension contains:
- threat feeds
- CVE objects
- security repositories
- offensive/defensive research
- anomaly alerts
- digital instability

---

## Atmosphere

Behavior:
- aggressive
- unstable
- reactive
- sharp
- fractured under high tension

Visual identity:
- signal fragmentation
- hostile pulse motion
- unstable geometry
- tension-reactive overlays

---

## Content Types

Allowed:
- tools
- CVE intelligence
- security repos
- malware analysis
- threat monitoring
- infrastructure anomalies

---

# 3. GitHub Signals

## Purpose

GitHub Signals represents:
the ecosystem's engineering memory.

This dimension tracks:
- repositories
- frameworks
- research systems
- infrastructure tools
- code ecosystems
- creator projects

---

## Atmosphere

Behavior:
- precise
- structured
- calm under low tension
- hyper-engineered

Visual identity:
- constellation systems
- lattice structures
- neural engineering grids
- monochrome precision

---

## Content Types

Allowed:
- repositories
- frameworks
- utilities
- infrastructure projects
- automation systems
- development research

---

## GitHub Object Behavior

When adding a repository:
the system should attempt to:
- fetch title
- fetch description
- fetch preview image
- detect language
- detect tags/topics

The creator should additionally define:
- why the repo matters
- ecosystem purpose
- influence type
- relationship behavior

---

# 4. OSINT Layer

## Purpose

OSINT Layer represents:
the ecosystem's investigative dimension.

It is:
a map of connections,
signals,
relationships,
and hidden structures.

---

## Atmosphere

Behavior:
- drifting
- investigative
- uncertain
- layered
- atmospheric

Visual identity:
- floating nodes
- signal links
- parallax drift
- hidden anomaly paths
- spatial uncertainty

---

## Content Types

Allowed:
- investigation nodes
- intelligence objects
- relationship maps
- signal trails
- entities
- research connections

---

## Important Rule

OSINT should NOT:
feel like a spreadsheet.

It should feel:
like exploring an unstable information network.

---

# 5. Cross-Dimension Behavior

Objects may exist across dimensions.

Example:
a GitHub repository may:
- appear in GitHub Signals
- trigger Cybersecurity anomalies
- create OSINT relationships

Dimensions are interconnected.

No dimension should feel isolated.

---

# 6. Environmental Continuity

World-state affects ALL dimensions simultaneously.

Examples:
- high tension destabilizes Cybersecurity
- rain softens GitHub Signals motion
- anomalies corrupt OSINT visibility
- nighttime alters atmosphere globally

The ecosystem should feel:
alive and connected.

---

# 7. Creator Guidance

Each dimension must explain:
- what belongs there
- what the dimension represents
- how objects behave inside it
- what ecosystem reactions may occur

The creator should never feel:
lost inside the ecosystem.
