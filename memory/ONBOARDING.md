# Onboarding & Guidance

## Philosophy
No operator should ever feel lost. The system must explain its own complexity semantically.

## Guided Flow
1. **Initial Protocol**: Explaining the authentication and role selection.
2. **Environmental Briefing**: Introducing the four primary dimensions.
3. **Manipulation Training**: How to use the Injection Protocol and Neural Mapping.
4. **Stability Protocol**: Understanding the "Live Diagnostics" and world-state safety rails.

## Empty States
- Each dimension should provide guidance if no objects are present.
- The Operator Workspace should use empty states to suggest the next logical action.

# ONBOARDING — NEXUS VEIL

## Core Principle

The ecosystem should NOT:
assume the operator understands the system immediately.

NEXUS VEIL is:
complex,
layered,
and atmospheric.

The onboarding system exists to:
guide without destroying mystery.

---

# 1. First Contact

The first interaction should feel:
intentional.

The gateway/login terminal should:
- feel cinematic
- feel reactive
- feel controlled
- establish atmosphere immediately

---

## Login Flow

Recommended sequence:

1. Gateway boot sequence
2. Login input
3. Password input
4. Identity recognition
5. Ecosystem synchronization
6. Role routing

---

## Important UX Behavior

Pressing ENTER on username:
should move focus to password.

Authentication should feel:
terminal-like,
not form-like.

---

# 2. Guest Onboarding

Guests should:
understand the ecosystem gradually.

Do NOT:
explain everything immediately.

Instead:
reveal systems progressively.

---

## Initial Guidance

Guests should understand:
- dimensions exist for different purposes
- atmosphere reacts dynamically
- anomalies may occur
- objects influence environments

---

## Suggested Guest Hints

Examples:
- "Signals react differently under high tension."
- "Some anomalies only emerge during environmental instability."
- "Dimensions are interconnected."

---

# 3. Operator Onboarding

Operators require:
a much deeper understanding.

The operator must understand:
- dimensions
- object types
- propagation
- relationships
- scenes
- world-state reactions

---

## Required Operator Guidance

The operator interface should explain:
- what every field does
- what danger levels mean
- how propagation behaves
- how relationships influence ecosystems
- how instability spreads

---

# 4. Interactive Guidance

The system should include:
- inline explanations
- contextual hints
- safe recommendations
- validation warnings
- ecosystem health indicators

---

## Examples

"This object may destabilize low-entropy dimensions."

"High signal strength may increase anomaly propagation."

"Recursive corruption relationships are blocked."

---

# 5. Empty-State Guidance

If a dimension contains no objects:
the system should explain:
- what belongs there
- how to add content
- what the dimension represents

Avoid:
empty confusing spaces.

---

## Example

GitHub Signals:
"Add repositories, frameworks, or engineering systems to populate this dimension."

OSINT Layer:
"Inject investigation nodes and relationships to build an intelligence network."

---

# 6. Discovery Philosophy

NEXUS VEIL should still contain:
mystery.

Not all systems should be explained directly.

Some:
- hidden routes
- anomalies
- rare events
- ecosystem mutations

should remain discoverable.

---

# 7. Creator Workflow Assistance

The ecosystem should assist the operator during creation.

Examples:
- suggested tags
- recommended dimensions
- relationship compatibility
- conflict prevention
- safe defaults

---

# 8. Error Communication

Errors should feel:
informative,
not technical.

Avoid:
raw framework errors.

Instead of:
"undefined state"

Prefer:
"Ecosystem synchronization failed."

---

# 9. Environmental Feedback

The ecosystem should communicate state changes visually and subtly.

Examples:
- atmosphere shifts
- audio changes
- signal distortion
- lighting changes
- interface instability

The operator should FEEL:
that the ecosystem reacted.

---

# 10. Final Principle

The onboarding system should make the ecosystem:
understandable,
without making it ordinary.
