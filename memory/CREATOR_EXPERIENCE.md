# Creator Experience (OPERATOR_WORKFLOW)

## Core Philosophy
The Operator interface is not an admin panel; it is a **controlled environmental manipulation interface**. The operator is an active participant in the ecosystem, and the tools should reflect this tactical, immersion-first approach.

## Operator Onboarding & Guidance
- **Contextual Awareness**: Every field in the creation and editing suites must have associated guidance.
- **Systemic Education**: The operator must understand how their actions (e.g., increasing Anomaly level) affect the global atmospheric state.
- **Safety Rails**: Conflict prevention and ecosystem stability checks must be integrated into the workflow.

## Practical Workflows
1. **Rapid Ingestion**: Support for template-based object creation to ensure consistent environmental properties.
2. **Tactical Mapping**: A simplified relationship editor to define how nodes interact and propagate influence.
3. **Environmental Auditing**: Real-time status monitoring of the ecosystem's "health" and stability.

## Guidance Tooltips (Conceptual)
- **Tension**: "Increases visual stiffness and reduces UI damping. High values cause brittle motion."
- **Entropy**: "Increases randomness and jitter. High values may cause periodic data corruption visuals."
- **Anomaly**: "Frequency of rare glitch events. Extreme values trigger global environment flashes."

## Stability & Safety
- **Conflict Prevention**: Warn if multiple objects have conflicting high-influence parameters in the same affinity.
- **Schema Validation**: Hard validation at the browser level before API injection.
- **Audio Feedback**: Subtle auditory cues for injection success, deletion, and system errors.

# CREATOR EXPERIENCE — NEXUS VEIL

## 1. Core Principle

The creator should never need:
- SSH access
- direct server editing
- manual JSON manipulation
- rebuilds for content updates
- touching registry files manually

All ecosystem management must happen:
through the browser interface.

The ecosystem should feel:
alive,
editable,
and operator-friendly.

---

## 2. Creator Priority Shift

The project has already evolved beyond:
a static atmospheric prototype.

The current priority is NOT:
- visual expansion
- cinematic experiments
- more ecosystem effects

The current priority IS:
# creator usability and operator workflow quality.

The ecosystem must become:
practical to use daily.

---

## 3. Operator Philosophy

The operator interface is NOT:
an admin dashboard.

It is:
a controlled ecosystem manipulation layer.

The creator should feel:
- in control
- informed
- guided
- safe from accidental ecosystem corruption

The system should assist:
not overwhelm.

---

## 4. Required Creator Workflow

The creator must be able to:

1. Create a knowledge object
2. Edit it later
3. Delete it safely
4. Assign it to dimensions
5. Assign it to scenes
6. Create relationships
7. Preview changes live
8. Observe ecosystem reactions instantly

WITHOUT:
- restarting the server
- editing code
- rebuilding the project

---

## 5. Tooltips & Explanations

Every important field requires:
- inline explanation
- influence description
- safe value ranges
- ecosystem effect explanation

Example:
signalStrength:
"Controls how strongly the object affects propagation and environmental tension."

dangerLevel:
"High values may destabilize low-entropy environments."

The creator should never guess field behavior.

---

## 6. Validation & Conflict Prevention

The ecosystem must protect itself from:
- recursive relationships
- corrupted metadata
- orphaned entities
- invalid scene assignments
- world-state saturation
- unstable propagation chains

The operator interface should:
warn before dangerous actions.

Examples:
- "This object may create unstable propagation loops."
- "High anomaly influence detected."
- "Scene entropy threshold exceeded."

recommended defaults and safe ranges.

predictable.
