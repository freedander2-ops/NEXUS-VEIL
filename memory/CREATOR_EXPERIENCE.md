# CREATOR EXPERIENCE — NEXUS VEIL

## 1. Core Principle

The creator should never need:
- SSH access
- direct server editing
- manual JSON manipulation
- rebuilds for content updates
- touching registry files manually

All ecosystem management must happen:
through the browser interface.

The ecosystem should feel:
alive,
editable,
and operator-friendly.

---

## 2. Creator Priority Shift

The project has already evolved beyond:
a static atmospheric prototype.

The current priority is NOT:
- visual expansion
- cinematic experiments
- more ecosystem effects

The current priority IS:
# creator usability and operator workflow quality.

The ecosystem must become:
practical to use daily.

---

## 3. Operator Philosophy

The operator interface is NOT:
an admin dashboard.

It is:
a controlled ecosystem manipulation layer.

The creator should feel:
- in control
- informed
- guided
- safe from accidental ecosystem corruption

The system should assist:
not overwhelm.

---

## 4. Required Creator Workflow

The creator must be able to:

1. Create a knowledge object
2. Edit it later
3. Delete it safely
4. Assign it to dimensions
5. Assign it to scenes
6. Create relationships
7. Preview changes live
8. Observe ecosystem reactions instantly

WITHOUT:
- restarting the server
- editing code
- rebuilding the project

---

## 5. Tooltips & Explanations

Every important field requires:
- inline explanation
- influence description
- safe value ranges
- ecosystem effect explanation

Example:
signalStrength:
"Controls how strongly the object affects propagation and environmental tension."

dangerLevel:
"High values may destabilize low-entropy environments."

The creator should never guess field behavior.

---

## 6. Validation & Conflict Prevention

The ecosystem must protect itself from:
- recursive relationships
- corrupted metadata
- orphaned entities
- invalid scene assignments
- world-state saturation
- unstable propagation chains

The operator interface should:
warn before dangerous actions.

Examples:
- "This object may create unstable propagation loops."
- "High anomaly influence detected."
- "Scene entropy threshold exceeded."

---

## 7. Templates & Quick Creation

The creator should not build every object manually.

Provide templates for:
- Repository
- Threat Feed
- OSINT Target
- Event Signal
- Intelligence Node
- Research Object
- Environmental Trigger

Templates should pre-fill:
recommended defaults and safe ranges.

---

## 8. Live Preview System

Before saving:
the creator should preview:
- object appearance
- dimensional behavior
- ecosystem influence
- relationship visibility

Changes should feel:
predictable.

---

## 9. Audio System Philosophy

Audio should be:
minimal,
tactile,
and atmospheric.

Avoid:
- loud UI sounds
- arcade effects
- aggressive cyberpunk clichés

Preferred sound behavior:
- soft interaction ticks
- muted digital pulses
- low ambient hum
- subtle anomaly distortion

Audio files must be externally replaceable.

Suggested structure:
/public/audio

The creator should be able to:
swap sounds without rebuilding the project.

---

## 10. Operator Guidance

The system must include:
- onboarding hints
- contextual recommendations
- ecosystem safety explanations
- first-time guidance

The creator should understand:
- what the ecosystem is doing
- why reactions happen
- how propagation spreads
- how world-state changes affect dimensions

---

## 11. Access Philosophy

Only authenticated operators may:
- modify ecosystem data
- inject objects
- alter scenes
- change relationships

Non-operators:
view-only access.

The ecosystem is personal infrastructure,
not a public editing platform.

---

## 12. Performance & Stability

Creator systems must prioritize:
- reliability
- persistence integrity
- runtime safety
- recovery behavior

A stable ecosystem is more important than:
visual complexity.

---

## 13. Final Principle

NEXUS VEIL should eventually feel like:

a personal atmospheric intelligence layer
that evolves alongside its operator.

Not:
a content dashboard.
